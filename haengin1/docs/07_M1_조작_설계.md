# 07. M1 조작·이동·카메라 설계 (3인칭)

> 대상: M1 그레이박스 — 혜화동 1구역(성대 후문~와룡공원)을 **걸어 다닐 수 있는 동네**로 만드는 데 필요한 조작·이동·카메라.
> 기준 문서: `01_기획서.md`(2장 용과 같이 문법, 4-1 조작, 9장 마일스톤), `03_맵_혜화동.md`(3.1 축척·보행 기준), `unity/README.md`(배치 명령·주의).
> 맵 쪽 짝 문서: `06_M1_그레이박스_설계.md` + `Assets/_Project/Data/zone1.json`(만드는 중, `tools/zone1_gen.py`). 맞춰야 할 것은 10장.
> 클래스·필드 이름은 `Library/PackageCache` 의 **Cinemachine 3.1.7**·**Input System 1.20.0** 소스를 직접 읽고 확인했다(부록 A). 이 문서를 쓰면서 Unity 는 실행하지 않았다.

## 0. 한눈에

| 항목 | 결정 |
|---|---|
| 이동 | `CharacterController` + 우리 `PlayerMotor`. 기본 걷기 **1.6 m/s**, 달리기 버튼을 누르는 동안 **4.5 m/s**. 점프 없음 |

| 시우 모델 | 리깅 전 정적 GLB 를 `Visual` 자식으로. 미끄러지듯 이동 + 앞으로 기울기(최대 8°)·회전 쪽 기울기(최대 8°) + 턱 오를 때 비주얼 높이 보정 |
| 상호작용 | `×`/`E` 자리만. 가까운 `Interactable` 을 고르고 프롬프트·로그만 낸다 |
| 락온 자리 | `L1`/`Q`·마우스 가운데. M1 에서는 **카메라를 등 뒤로 정렬**, M2 에서 락온으로 확장 |

## 1. M1 범위

### 1-1. 정하는 기준

- 기획서 9장: M1 = "Unity 프로젝트, 혜화동 1구역 회색 박스 맵, 3인칭 이동" → 결과물 **"걸어 다닐 수 있는 동네"**. 전투는 M2.
- 기획서 1장: "탐험은 숄더뷰, 전투는 락온". 2장: 인카운터는 **로딩 없이 그 자리가 전장** → 탐험 조작·카메라가 전투로 끊김 없이 넘어갈 수 있게 구조만 미리 잡는다(입력 맵 분리, 카메라 우선순위).
- 기획서 4-1(패드): □ 약공격, △ 강공격, ○ 잡기, × 회피, R1 가드, L1 락온. → 이 버튼들은 **전투 맵(M2)** 에 예약하고, 탐험 맵에서는 겹치지 않게 또는 의미가 이어지게 배치한다.

### 1-2. M1 에서 하는 것 / 자리만 / 안 하는 것

| 구분 | 내용 |
|---|---|
| **구현** | 걷기(패드 기울기만큼 느리게도), 달리기(누르는 동안), 카메라 회전(마우스·오른스틱), 카메라 등 뒤 정렬(L1/Q), 달릴 때 FOV·거리 변화, 카메라 충돌 회피, 중력·턱·경사·낙하·맵 밖 리스폰, 시우 정적 모델 + 몸 기울기, 디버그 표시(F1) |
| **자리만** | 상호작용(× / E): 가장 알맞은 대상 1개 고르기 + 프롬프트 + 로그. 일시정지(Options / Esc)는 2차에서 **메뉴까지 구현**(계속·카메라 자동 정렬·끝내기, 패드·키보드·마우스). 락온(L1 / Q): 대상이 없을 때의 동작(카메라 정렬)만 |
| **안 함** | 공격·잡기·회피·가드(M2), 실제 락온, 점프(기획에 없음 — 용과 같이도 맨손 점프가 없다), 웅크리기, 전력질주(10장 질문 3), 자전거·배달 탈것, 실내 씬 전환, NPC, 걷기 애니메이션(리깅 전) |

## 2. 입력

### 2-1. 입력 표

패드 표기는 기획서처럼 PS 기호를 먼저, Xbox 이름을 괄호에 쓴다(PC 패드는 대부분 Xbox 배치).

| 동작 | 키보드·마우스 | 패드 PS (Xbox) | M1 | 비고 |
|---|---|---|---|---|
| 이동 | W A S D (방향키 보조) | 왼스틱 (LS) | 구현 | 패드는 기울기만큼 걷기 속도 0.5~1.6 m/s |
| 카메라 | 마우스 이동 | 오른스틱 (RS) | 구현 | Y 반전 기본 끔(옵션) |
| 달리기 | 왼쪽 Shift 누르고 있기 | R2 (RT) 누르고 있기 | 구현 | 옵션: L3 (LS 누름) = 달리기 토글 |
| 상호작용 | E | × (A) | 자리 | 대상이 있을 때만 프롬프트 |
| 락온 자리 / 카메라 등 뒤로 | Q 또는 마우스 가운데 버튼 | L1 (LB) | M1 = 카메라 정렬 | M2: 대상이 있으면 락온, 없으면 지금처럼 정렬 |
| 일시정지 | Esc | Options (Menu) | 구현(2차) | 시간 정지·커서 풀기 + 메뉴. 다시 누르면 계속 |
| 메뉴 고르기 | ↑ ↓ (W S) | 십자키 · 왼스틱 위아래 | 구현(2차) | 누르고 있으면 0.4초 뒤 0.15초마다 반복. '카메라 자동 정렬' 항목은 ← → 로도 바꿈 |
| 메뉴 선택 | Enter · Space · 마우스 왼쪽 | × (A) | 구현(2차) | 탐험의 상호작용과 같은 버튼(PS5 이후 확인 = ×) |
| 메뉴 돌아가기 | Esc · Backspace | ○ (B) | 구현(2차) | 메뉴를 닫고 계속 |
| 디버그 표시 | F1 | — | 개발용 | 속도·상태·카메라 거리·FOV·초당 프레임 |

**전투 맵(M2) 예약** — 기획서 4-1 그대로: □ (X) 약공격 / △ (Y) 강공격 / ○ (B) 잡기 / × (A) 회피 / R1 (RB) 가드 / L1 (LB) 락온. 키보드 제안(M2 에서 결정): 약공격 마우스 왼쪽, 강공격 마우스 오른쪽, 잡기 F, 회피 Space, 가드 왼쪽 Ctrl, 락온 Q·마우스 가운데.

**왜 이렇게**
- **상호작용 = × (A)**: PS5 이후 확인 버튼이 ×로 통일됐고 Xbox 패드의 A(아래)와 같은 자리다. ×는 전투에서 회피지만 탐험과 전투는 맵이 달라 부딪히지 않는다(인카운터 시작 = 맵 전환). ○는 전투의 잡기라 탐험에서 비워 둔다. 일본식 ○ 확인을 원하면 바꾸기 쉽다(10장 질문 1).
- **달리기 = R2 누르고 있기**: 왼손 엄지는 이동, 오른손 엄지는 카메라라서 달리면서 카메라를 돌리려면 검지(트리거)가 맞다. L3 누르고 있기는 오래 하면 손이 아프고, ×는 상호작용과 겹친다.
- **L1 = 락온 자리**: 탐험 중 L1 은 "카메라를 등 뒤로" — 대상이 없을 때의 락온 버튼 동작으로 흔한 방식이라, M2 에서 같은 버튼이 그대로 락온이 된다.
- **기본이 걷기**: 기획서 9장 결과물이 "걸어 다닐 수 있는 동네"이고, 1구역은 짧아서(체크포인트 1→10 약 230 m 추정, 걷기 2분 반·달리기 50초) 동네를 보면서 걷는 것이 기본 경험이다. 빨리 가고 싶을 때 달린다.

### 2-2. 입력 에셋

- 파일: `Assets/_Project/Input/HInput.inputactions` (손으로 쓴 JSON 을 커밋. 템플릿 `Assets/InputSystem_Actions.inputactions` 는 건드리지 않는다)
- 맵 `Explore` (M1). 맵 `Combat` 는 M2 에서 추가. 한 번에 한 맵만 켠다.

| 액션 | 형식 | 바인딩 | 처리기·상호작용 |
|---|---|---|---|
| `Move` | Value / Vector2 | `<Gamepad>/leftStick`, 2DVector 합성(W/S/A/D, 방향키) | 합성 모드 DigitalNormalized. 스틱 데드존은 패드 레이아웃 기본값(`stickDeadzone` 0.125~0.925)을 그대로 쓴다 |
| `LookPad` | Value / Vector2 | `<Gamepad>/rightStick` | (기본 데드존) |
| `LookMouse` | Value / Vector2 | `<Mouse>/delta` | 없음. 값은 "이번 프레임 픽셀" |
| `Run` | Button | `<Keyboard>/leftShift`, `<Gamepad>/rightTrigger` | 없음(누르는 동안 `IsPressed()`) |
| `RunToggle` | Button | `<Gamepad>/leftStickPress` | 옵션이 켜졌을 때만 읽음 |
| `Interact` | Button | `<Keyboard>/e`, `<Gamepad>/buttonSouth` | **Press** (템플릿의 Hold 는 쓰지 않음) |
| `LockOn` | Button | `<Keyboard>/q`, `<Mouse>/middleButton`, `<Gamepad>/leftShoulder` | Press |
| `Pause` | Button | `<Keyboard>/escape`, `<Gamepad>/start` | Press |
| `DebugHud` | Button | `<Keyboard>/f1` | Press |

맵 `Menu`(2차, 일시정지 메뉴 전용 — `GameUi` 가 읽음. 탐험 맵과 함께 켜 두고 일시정지 중에만 쓴다):

| 액션 | 형식 | 바인딩 |
|---|---|---|
| `Navigate` | Value / Vector2 | `<Gamepad>/dpad`, `<Gamepad>/leftStick`, 2DVector 합성(방향키), 2DVector 합성(W/S/A/D) |
| `Submit` | Button | `<Gamepad>/buttonSouth`, `<Keyboard>/enter`, `<Keyboard>/numpadEnter`, `<Keyboard>/space` |
| `Cancel` | Button | `<Gamepad>/buttonEast`, `<Keyboard>/backspace` |

- 열기·닫기는 따로 액션을 두지 않고 탐험 맵의 `Pause`(Esc·Options)를 그대로 쓴다 — 같은 버튼으로 열고 닫는 것이 패드 게임의 관례.
- 누름 판정은 `WasPressedThisFrame()` 에 더해 '지난 프레임엔 안 눌렸는데 지금 눌림'도 본다(`GameUi.Edge`). 프레임 밖에서 처리되는 입력(테스트의 가짜 장치)도 놓치지 않는다.

- 시점을 `LookPad`·`LookMouse` 두 액션으로 나눈 이유: 마우스 델타는 "프레임당 픽셀"(이미 시간이 곱해진 값)이고 스틱은 "−1~1 기울기"(속도로 바꿔야 하는 값)라 감도·시간 처리가 다르다. 한 액션에 묶으면 장치를 매 프레임 가려 내야 한다.
- 컨트롤 스킴(Keyboard&Mouse / Gamepad)은 바인딩 그룹 표시용으로만 두고, 두 장치를 동시에 받는다(싱글 플레이 PC).

### 2-3. 읽는 방식 — `.inputactions` + `InputActionReference`

검토한 세 가지:

| 방식 | 판단 |
|---|---|
| `PlayerInput` 컴포넌트 | 쓰지 않음. 장치 짝짓기·SendMessage·이벤트 연결이 1인용 PC 게임에 불필요하고, 배치로 장면을 만들 때 설정할 것이 많다 |
| 생성 C# 클래스(`new HInput()`) | 쓰지 않음. 생성 클래스는 **에셋과 별개의 액션 인스턴스**를 만든다. 카메라 쪽(그리고 나중에 UI)이 에셋의 `InputActionReference` 를 쓰면 같은 액션이 두 벌 생겨 켜고 끄기가 어긋난다 |
| **에셋 + `InputActionReference`** | **채택.** 장면 생성 스크립트가 에셋의 하위 에셋(`InputActionReference`, 이름 `Explore/Move` 등)을 컴포넌트 필드에 꽂는다. 액션 인스턴스가 하나뿐이고, 테스트에서는 `InputActionReference.Create(action)` 으로도 만들 수 있다 |

- 맵 켜기: `PInput.OnEnable()` 에서 `Move.action.actionMap.Enable()`.
- 프로젝트 전역 액션(`InputSystem.actions`, 지금은 템플릿 에셋이 지정돼 있음)은 M1 에서 바꾸지 않는다. 템플릿 액션도 시작 때 켜지지만 아무도 읽지 않으니 해가 없다(정리는 10장 질문 8).

## 3. 이동

### 3-1. 속도 — 근거

| 값 | 숫자 | 근거 |
|---|---|---|
| 걷기 | **1.6 m/s** (5.8 km/h) | 성인 편한 걸음 1.3~1.4 m/s(03_맵 3.1 은 1.4 기준)보다 조금 빠른 17세의 "바쁜 걸음". 게임은 실제보다 조금 빨라야 답답하지 않다. 맵 전체(약 490 m)를 걸으면 5.1분 → 기획서 2장 "걸어서 5~7분이면 끝에서 끝"과 맞는다 |
| 패드 느린 걷기 | 0.5 m/s ~ 1.6 m/s | 스틱 기울기 0.0~0.9 를 선형으로. 0.9 이상은 1.6 고정(스틱 끝 데드존) |
| 달리기 | **4.5 m/s** (16.2 km/h, 1 km 3분 42초) | 걷기의 2.8배 — 둘이 확실히 다르게 느껴지는 차이. 맵 전체 1.8분 → 03_맵 3.1 "달리기면 약 2~3분"과 맞는다. 밴텀급 고등학생이 골목을 뛰는 속도로 무리가 없고, 경사가 실제의 2배인(수직 1/2 압축) 언덕에서도 답답하지 않다 |
| 전력질주 | 없음 | 06 쪽 `zone1.json` 메타에 `sprint 6.0` 이 적혀 있으나 M1 범위 밖(10장 질문 3) |

1구역 체크포인트 1→10(성대 후문 → 와룡공원 전망 쉼터)은 길 기준 약 230 m(추정) → 걷기 약 2분 25초, 달리기 약 50초. 실제 길이는 테스트(9장 T14)가 NavMesh 경로로 재서 로그에 남긴다.

### 3-2. 가속·감속·회전

애니메이션이 없어 "미끄러지는 조각상"처럼 보이기 쉽다. 그래서 **출발·정지는 짧게**, 방향 전환에만 약간의 무게를 준다.

| 값 | 숫자 | 비고 |
|---|---|---|
| 0 → 걷기 | 0.12초 (13.3 m/s²) | 누르자마자 나간다 |
| 걷기 → 달리기 | 0.40초 (7.25 m/s²) | 0 → 달리기는 약 0.5초. 달리기는 "붙는" 느낌 |
| 정지(감속) | 18 m/s² | 달리기에서 0.25초·0.56 m, 걷기에서 0.09초·0.08 m. 얼음 위처럼 미끄러지지 않게 |
| 속도 계산 | 평면 속도 벡터를 목표 벡터로 `MoveTowards` | 급반전하면 자연히 0 을 거쳐 감속 → 방향 전환에 무게 |

### 3-5. 레이어 (M1 에서 새로 정함 — 06 빌더와 합의 필요)

| 번호 | 이름 | 무엇 | 플레이어 | 카메라 |
|---|---|---|---|---|
| 0 | Default | 레이어를 안 정한 것(안전망) | 막힘 | 막힘 |
| 6 | `Ground` | 지형·길·인도·골목·패드·**계단 경사로 충돌체** | 걷는 면 | 막힘 |
| 7 | `Wall` | 건물·담·성곽·옹벽·문틀·경계 상자(눈에 보이는 것) | 막힘 | 막힘 |
| 8 | `Player` | 플레이어 캡슐 | — | 무시 |
| 9 | `PlayerOnly` | 전봇대·가로등·표지판·난간·나무 줄기·버스 정류장·**보이지 않는 경계벽** | 막힘 | **무시**(통과) |
| 10 | `Interact` | 상호작용 트리거 | 트리거 | 무시 |
| 11 | `CamBlock` | 카메라만 막는 보이지 않는 벽(맵 가장자리 미완성 구역 가리기) | 통과 | 막힘 |

- 물리 충돌 행렬: `Player`×`CamBlock` 끔. 나머지 기본.
- 얇은 물체를 `PlayerOnly` 로 두는 이유: 골목에는 전봇대·가로등이 많다. 이것들이 카메라를 막으면 지나갈 때마다 카메라가 앞으로 툭툭 당겨진다. 가늘어서 가려도 인물이 거의 다 보인다.
- **2차 점검 — '얇다'의 기준은 두께가 아니라 화면에서 가리는 넓이**: 카메라가 통과해도 되는 것은 화면에서 가는 기둥·성긴 난간처럼 뒤가 비쳐 보이는 것뿐이다. 캠퍼스 담장(높이 2.8~3m)·닫힌 후문 차단 펜스(5m×2.5m)는 두께가 0.3m 라도 **판**이라서 `Wall` 로 둔다(빌더 `BlockLayer`: fence·barrier → Wall). 판을 `PlayerOnly` 로 바꾸면 카메라가 판을 통과해 그 뒤에 서고, 판이 화면 아래를 통째로 덮는다(시작 화면 문제의 원인이 판 자체였음). 그래서 시작 화면 문제는 레이어가 아니라 **시작 자리**로 고쳤다(4-9). 위 표의 '울타리'는 판 모양 담장이 아니라 성긴 울타리(난간 kind `railing`)를 뜻한다.

### 3-6. 맵에 요청하는 규칙 (06 과 맞출 것)

1. **계단 충돌 = 경사로.** 보이는 계단 단은 충돌체 없이 그리고, 같은 자리에 기울어진 상자(또는 메시) 충돌체를 `Ground` 로 둔다. 단마다 충돌하면 0.18 m 씩 턱을 오르느라 몸·카메라가 초당 10~15번 들썩인다(달리기 4.5 m/s ÷ 단 너비 0.3 m). 1구역 계단 5개의 각도는 16.2~27.1°(`zone1.json` 2026-10-05 생성본: 단 높이 0.16~0.18 m, 폭 1.6~3.0 m)라 slopeLimit 40° 안이다.
2. 올라가야 하는 턱 ≤ 0.30 m, 막아야 하는 턱 ≥ 0.45 m. 그 사이(0.31~0.44)는 만들지 않는다.
3. 걸어 다니는 길 위 2.3 m 아래에 낮은 천장·간판 아래면을 두지 않는다(카메라가 인물 머리 위 0.6 m 로 지나감).
4. 경계벽은 `PlayerOnly`(카메라는 밖을 볼 수 있게). 미완성 구역을 가리고 싶으면 `CamBlock` 을 따로.
5. 시작 지점은 `zone1.json` 의 `spawn`(pos, yaw: 위에서 볼 때 시계 방향 +, 0 = 북쪽 +Z). Unity Y 회전과 같은 뜻이라 그대로 쓴다.

## 4. 카메라

### 4-1. 구성 결정 — 왜 OrbitalFollow 인가

| 후보 | 판단 |
|---|---|
| `CinemachineThirdPersonFollow` | 어깨 오프셋(`ShoulderOffset`·`CameraSide`)과 충돌 처리(`AvoidObstacles`)가 들어 있지만, 카메라 방향을 **따라가는 대상의 회전**에서 가져온다 → 우리가 회전용 물체를 따로 돌려야 하고, 자동 정렬·피치 제한을 다 직접 짜야 한다. 충돌은 "대상→손→카메라" 구체 검사뿐이라 지나가는 전봇대처럼 **잠깐 가리는 것**에도 바로 당겨진다(최소 가림 시간·투명 레이어 개념 없음) |
| **`CinemachineOrbitalFollow` (Sphere)** + `CinemachineRotationComposer` + `CinemachineDeoccluder` | **채택.** 궤도 축(`HorizontalAxis`/`VerticalAxis`)에 범위·되감기·**자동 정렬(Recentering)**이 들어 있고, 정렬 기준을 "따라가는 대상의 정면"으로 둘 수 있다(`RecenteringTarget = TrackingTarget`). 가림 처리는 `Deoccluder` 가 레이어·태그·당기기/복귀 감쇠를 따로 준다 |
| `CinemachineDecollider` | 기본 구성에는 넣지 않는다. 카메라가 지형 아래로 들어가는 경우가 테스트(T09·T14)에서 나오면 `TerrainResolution`(지형 레이어 = Ground) 만 켜서 덧붙인다 |
| `CinemachineCameraOffset` | 진짜 위치 오프셋(어깨 위)이 필요해지면 쓰는 대안. 다만 확장 실행 순서에 따라 충돌 처리 **뒤에** 카메라를 옮겨 벽 안으로 넣을 수 있어 M1 에서는 쓰지 않는다 |
| `CinemachineInputAxisController` | 쓰지 않는다(4-5 참고). 대신 우리 `CamInput` 이 궤도 축 값을 직접 바꾼다 |

### 4-4. 이동 기준 방향 = 궤도 정면 (중요)

인물이 움직이는 기준은 **카메라 정면(`Camera.main.transform.forward`)이 아니라 궤도 정면** `Quaternion.Euler(0, Orbit.HorizontalAxis.Value, 0)` 이다.

- 이유: 구도 오프셋(−0.06) 때문에 카메라 정면은 궤도선(카메라→인물)보다 약 5° 오른쪽을 본다. 카메라 정면을 기준으로 앞으로 가면 인물은 5° 오른쪽으로 걷고, 달릴 때 자동 정렬이 카메라를 인물 등 뒤로 다시 맞추면 또 5° … **계속 오른쪽으로 빙글 도는 되먹임**이 생긴다.
- 궤도 정면을 쓰면 "앞"을 누르는 동안 인물은 화면의 같은 자리(중앙에서 6% 왼쪽)에 머문 채 안쪽으로 걸어 들어간다. T13 이 6초 달리기 후 방향 변화 1° 이하인지 본다.
- `HorizontalAxis.Value` 는 `WorldSpace` 바인딩에서 그대로 월드 yaw 다(카메라 위치 = 대상 + `Euler(pitch, yaw, 0)·(0,0,−R)`, 소스 확인).
- 다른 카메라가 살아 있을 때(M2 전투·컷신)는 `CinemachineBrain` 출력 카메라의 yaw 로 바꾼다 — `CamRig.MoveBasis` 하나로 감싼다.

### 4-5. 시점 입력 — `CinemachineInputAxisController` 를 쓰지 않는 이유

`CinemachineInputAxisController` 는 축마다 액션 하나(`Reader.InputAction`)를 읽고 `Gain`·`CancelDeltaTime`·`Driver.AccelTime/DecelTime` 을 **그 축 전체에** 적용한다. 마우스(프레임당 픽셀 → 시간으로 나누기, 가속 0)와 스틱(속도 → 응답 곡선)을 한 축에서 다르게 처리하려면 `ReadControlValueOverride` 에서 장치를 가려 다시 계산해야 해서, 결국 우리 코드가 필요하다. 그렇다면 축을 직접 쓰는 편이 짧고, 테스트에서 `CamInput.Rotate(dYaw, dPitch)` 로 똑같은 경로를 탈 수 있다.

- 축 값을 직접 바꿔도 `OrbitalFollow` 가 매 프레임 `TrackValueChange()` 로 변화를 감지하므로 자동 정렬 대기 시간이 정상으로 다시 시작된다(소스 확인).
- 마우스: `dYaw = delta.x × 0.08 × 배율` (시간 곱하지 않음 — 델타가 이미 프레임 동안 움직인 양).
- 스틱: `dYaw = sign(x)·|x|^1.6 × 150 × 배율 × Time.unscaledDeltaTime` (일시정지·히트스톱 중에도 카메라는 돈다. 일시정지 중엔 `CamInput` 자체를 끈다).
- 피치: 위로 밀면 위를 본다 = 카메라가 내려간다 = `VerticalAxis.Value` 감소. 그래서 반전이 꺼져 있으면 `dPitch = −(…)`.

### 4-6. 달릴 때 FOV·거리

- `run01 = InverseLerp(1.6, 4.5, PlanarSpeed)` — 버튼이 아니라 **실제 속도**에 묶는다. 멈추면 저절로 돌아오고, 벽에 막혀 못 뛰면 FOV 도 안 바뀐다.
- FOV = Lerp(45, 49, run01), 거리 = Lerp(4.0, 4.3, run01). `SmoothDamp` 시간: 커질 때 0.6초, 작아질 때 0.4초.
- 이보다 크게 바꾸지 않는다(+4°, +0.3 m). 크게 바꾸면 달리기 시작·멈춤마다 화면이 숨 쉬듯 출렁인다.

### 4-7. 「용과 같이」 느낌을 위한 원칙 (점검표)

**조용한 카메라 — 출렁이지 않게**
1. 탐험 중 카메라 노이즈(`CinemachineBasicMultiChannelPerlin`) 0. 흔들림은 M2 전투 임펄스(`CinemachineImpulseSource`/`Listener`)에서만.
2. 수직 움직임을 카메라에 넘기지 않는다: 계단 = 경사로 충돌(3-6), 위아래 위치 감쇠 0.40, 턱을 오를 때 비주얼 높이 보정(5-3).
3. 플레이어가 돌려 놓은 카메라를 **곧바로** 되돌리지 않는다. 자동 정렬은 수동 조작 뒤 기다렸다가(걷기 1.8초·달리기 1.2초) 천천히(각속도 제한) — 2차 변경, 4-8.
4. 앞질러 보기(Lookahead)·데드존 끔. 조준 감쇠는 작게(0.10/0.20) — 위치는 늦게, 조준은 바로.
5. FOV·거리 변화는 작고 느리게(4-6). 인물 속도에 묶는다.
6. 구도 고정: 인물 화면 높이 약 50%, 발 아래 여백 10%, 가로 중앙에서 6% 왼쪽.

**벽을 뚫지 않게 — 골목**
7. 가림 검사는 인물 몸 안(CamTarget, 1.40 m)에서 카메라 쪽으로 반지름 0.10 구체를 쏜다(`MinimumDistanceFromTarget` 0.01). 시작점이 캡슐 반지름(0.25) 안이라 등을 벽에 붙여도 검사가 벽 앞에서 시작한다.
8. 들어갈 때는 즉시(`DampingWhenOccluded` 0, `MinimumOcclusionTime` 0), 나올 때는 0.5초. 모서리에서는 0.25초 동안 가까운 거리를 유지.
9. 근평면 0.08 → 옆벽에 붙어도 근평면 모서리(옆으로 0.068 m)가 카메라 반지름(0.10) 안.
10. 얇은 것(전봇대·가로등·난간·나무)은 `PlayerOnly` 로 카메라가 통과 → 지나갈 때 툭툭 당겨지지 않는다. 보이지 않는 경계벽도 `PlayerOnly`.
11. 너무 가까우면(0.55 m) 인물을 숨긴다(그림자는 남김).
12. 맵 규칙: 걷는 길 위 2.3 m 아래 천장 없음, 골목 폭 ≥ 2.4 m(06 의 가장 좁은 계단 1.6 m 는 T14 에서 특히 본다).

**전투로 이어지게(M2 대비)**
13. 탐험 카메라 우선순위 10. 전투 카메라는 20 으로 올렸다 내리고 브레인 기본 블렌드 0.4초로 넘어간다(로딩 없는 인카운터).
14. 이동 기준은 `CamRig.MoveBasis` 하나로 — 전투 카메라가 살아 있으면 그 카메라 기준.

### 4-8. 걷기 자동 정렬 (2차 변경 — 1차의 '걸을 때는 정렬 없음'을 뒤집음)

**무엇이 문제였나**: 1차는 "플레이어가 돌려 놓은 카메라를 걷는 중에 되돌리지 않는다"를 지키려고 걷기에서 자동 정렬을 껐다. 그런데 1구역은 걷기가 기본(2-1)이고 길이 계속 꺾인다(상가 뒤 골목 → 주차장 → 명륜3가 골목 → 계단 → 성곽길). 대표가 패드로 걸어 보니 모퉁이마다 오른스틱을 만져야 했다. 「용과 같이」(0·극·7 이후)는 걸을 때도 잠시 뒤 카메라가 천천히 등 뒤로 돌아오고, 막 돌려 놓은 카메라는 그 몇 초 동안 존중한다. 두 원칙(돌려 놓은 시점 존중 + 꺾이는 길 따라가기)은 **기다림 시간**으로 같이 지킬 수 있다.

**방식**: Cinemachine 의 정렬(`Recentering`)은 SmoothDamp 라서 최고 각속도가 남은 각도에 비례한다(Time 2초면 차이 150° 에서 약 110°/s, 90° 에서 66°/s). 지그재그 골목·계단에서는 큰 각도가 자주 생겨 화면이 출렁인다. 그래서 탐험 자동 정렬은 `CamRig` 가 직접 한다.
- 원하는 각속도 = (인물 몸 방향 − 궤도 yaw) × 1.2/s, 최대 걷기 30°/s(패드를 살짝 기울인 느린 걷기는 속도 비율만큼 더 느리게)·달리기 60°/s.
- 실제 각속도는 각가속도 제한(걷기 60°/s², 달리기 120°/s²)으로 원하는 값에 다가간다 → 시작·멈춤·방향 바뀜이 부드럽다. 목표를 지나치지 않게 마지막 걸음은 자른다.
- 기다림: 마지막 수동 시점 조작(마우스·오른스틱, `CamRig.NoteManualLook`) 뒤 걷기 1.8초·달리기 1.2초. 움직이기 시작한 뒤 0.3초(제자리 방향 바꾸기·톡 입력에는 안 돔).
- 안 돌리는 경우: 서 있을 때 · 공중 · 인물이 카메라 쪽으로 걸어올 때(궤도와 몸 방향 차 ≥ 150° — 180° 휙 돌기 방지, 얼굴 보며 걸어오는 장면 존중) · Q/L1 정렬 중(그건 Cinemachine 강제 정렬 0.3초).
- 세로(피치)도 같은 방식으로 3초 뒤 기본 8° 로 최대 12°/s.
- Cinemachine 정렬은 `Wait` 를 늘 9999 로 두고 Q/L1(`TriggerRecentering`)에만 쓴다. `Recentering.Enabled` 는 켜 둔다(그래야 `Center` 가 인물 정면으로 갱신된다). 우리 쪽에서 축 값을 바꾸면 Cinemachine 이 '입력'으로 보고 강제 정렬을 취소하므로 Q/L1 정렬 중에는 손대지 않는다.

**수치 근거**: 걷기 1.6 m/s 로 90° 모퉁이를 돌면 정렬에 약 3.5초(기다림 포함 약 5초) — 모퉁이 하나를 지나 다음 골목이 보일 무렵 등 뒤에 온다. 30°/s 는 1.6 m/s 로 걸을 때 4 m 뒤 카메라가 옆으로 2.1 m/s 쯤 움직이는 속도라 인물 걸음보다 약간 빠른 정도. 달리기 60°/s 도 같은 비율(4.5 m/s). T19 실측: 걷기 90° → 기다림 1.80초, 최대 30.0°/s, 최대 각가속도 60°/s², 넘침 0°, 6.9초에 1° 안 · 달리기 1.20초, 60.0°/s, 5.4초. 1구역 자동 걷기(T14)에서 카메라가 등 뒤로 따라오면서 평균 거리 3.81 → 4.05m, 최소 거리 1.22 → 3.17m(골목에서 옆벽에 덜 붙음).

**옵션**: 일시정지 메뉴 '카메라 자동 정렬' = 걷기·달리기(기본) / 달리기만(1차 방식) / 끔. 빌드에서는 고른 값을 `PlayerPrefs`(`haengin.cam.autoAlign`)에 남긴다(배치·테스트에서는 안 남김). 기본값은 `CamTuning.autoRecenter`.

**대표 확인할 것(11장 11)**: 기다림 1.8초·걷기 30°/s 는 첫 값이다. 패드로 걸어 보고 너무 늦거나 빠르면 `CamTuning` 숫자만 바꾸면 된다.

### 4-9. 시작 구도 (2차)

1차 시작 자리(성대 후문 앞 남쪽 인도, 닫힌 후문 차단 펜스 앞 2m, yaw 32°)는 등 뒤 4m 카메라가 펜스(높이: 그 자리 발에서 1.57m) **너머**에 놓였다. 카메라 높이(1.96m)는 펜스보다 높지만 펜스가 화면 아래(인물 다리)를 가려서 `CamClearance` 다리 가림 검사가 카메라를 2.16m 로 당겼다 → 인물이 화면 2/3, 무릎 아래가 잘림(4-3 기준 위반).

고친 것: 시작 자리를 **차도 남쪽 차선(연석에서 2m, 펜스에서 4.5m)** 으로 2.5m 앞에 두고 yaw 34° (`zone1_gen.py` 6장 `road_pt(-197.6, -1.5)`). 카메라가 펜스·서쪽 기둥 앞 인도 위(가장 가까운 기둥까지 1.2m)에 오고 무릎→카메라 선이 막히지 않는다. 결과(T21): 거리 4.00m · 당김 0 · 발 10% · 정수리 60% → 인물 50%, 가로 0.44. 화면 왼쪽 위에 성곽·와룡공원 이름표, 오른쪽에 다음 체크포인트(후문 상가거리) 빛 기둥, 위 가운데 HUD "다음: 후문 상가거리 · 19m".
- 레이어로 고치지 않은 이유는 3-5 끝(펜스는 판이라 Wall).
- 달리기 컷(1차 2.42m)은 자동 정렬로 카메라가 등 뒤(길 쪽)에 오면서 함께 풀렸다: 3초 달린 뒤 거리 4.58m(4.3 + 위치 감쇠 지연)·당김 0·FOV 49·인물 40%.

### 5-3. 턱 보정

`CharacterController` 가 0.15~0.30 m 턱을 한 프레임에 오르거나 스냅으로 내려가면 모델이 툭 뛴다. 한 프레임 루트 높이 변화가 0.05 m 를 넘고 앞뒤 프레임 모두 접지였으면 그만큼을 `Visual` 의 로컬 y 에 반대로 더해 두고, 0.08초 시간상수로 0 까지 줄인다. 경사로의 연속적인 오르내림(프레임당 0.05 m 이하)은 건드리지 않아 발이 땅에 묻히지 않는다.

- `Interactable`(대상): `Label`("하루편의점" 등), `Prompt`("들어가기"), `M1Note`("M1: 아직 열리지 않음"), `OnInteract`(UnityEvent), `Enabled`. `Interact` 레이어의 트리거 구(반지름 0.6) 하나.

- 프롬프트: 화면 아래 가운데 IMGUI 한 줄 `[E / ×] 하루편의점 들어가기`. M1 은 누르면 2초 토스트 "아직 열리지 않았어요(M1)".
- 1구역 배치 후보(06 의 문·랜드마크에서): 하루편의점 문, 번개배달 사무실 문, 성대후문 국밥 문, 반시우의 집 문, 꼭대기 다세대 출입문, 전봇대 전단지 보드, 마을버스 정류장, 와룡공원 벤치. 이름은 모두 가상 가게 이름(하루편의점 등)이고 랜드마크(성대 후문·와룡공원·성곽)만 실명.

Update():
    dt = Time.deltaTime
    in = 이번 프레임 입력(없으면 0) ; 입력 비우기
    dir = 수평화(in.worldDir).normalized ; amt = clamp01(in.amount)

    // 목표 속도
    if amt < 0.01: target = 0
    else:
        walk = lerp(minWalkSpeed, walkSpeed, clamp01(amt / stickFull))
        target = dir * (in.run && amt > 0.5 ? runSpeed : walk)

    // 가감속 — 평면 속도 벡터를 목표로
    cur = planarVel ; spd = |cur|
    if |target| > spd and dot(cur, target) >= 0:
        rate = spd < walkSpeed ? walkSpeed / walkAccelTime : (runSpeed - walkSpeed) / runAccelTime
    else rate = decel
    planarVel = MoveTowards(cur, target, rate * dt)

    // 몸 방향 — 입력 방향으로, 상한 회전 속도
    if amt > 0.1:
        yaw = MoveTowardsAngle(yaw, atan2(dir.x, dir.z), (State==Run ? turnRateRun : turnRateWalk) * dt)
        transform.rotation = Euler(0, yaw, 0)

    // 땅·중력
    if grounded:
        n = GroundNormal
        if angle(n, up) > slopeLimit + 2: planarVel += downhill(n) * slideSpeed     // 걸터앉기 방지
        move = ProjectOnPlane(planarVel, n) + down * groundStick
        vy = 0
    else:
        vy = max(vy - gravity * dt, -maxFall)
        move = planarVel + up * vy
    y0 = position.y
    flags = cc.Move(move * dt)
    if flags has Sides: planarVel = 벽 법선 성분 제거 (벽에 붙어 미는 속도 누적 방지)

    // 스냅
    if wasGrounded and not cc.isGrounded and vy <= 0 and SphereCast(아래, snapDistance) hit 걸을 수 있는 면:
        cc.Move(down * hit.distance)

    grounded = cc.isGrounded || 짧은 SphereCast(0.05)  ; GroundNormal 갱신
    StepDeltaY = (위아래 변화 중 경사 투영으로 설명 안 되는 몫; |Δy| > stepThreshold 이고 앞뒤 접지일 때만)

    PlanarSpeed·PlanarAccel·YawRate·Velocity 갱신
    0.5초마다 (grounded && 경사 OK) 이면 LastSafePos 기록
    position.y < killY 이면 Teleport(LastSafePos, yaw)

### 7-6. `CamInput`·`CamRig`

```csharp
[DefaultExecutionOrder(-40)]
public sealed class CamInput : MonoBehaviour
{
    public InputActionReference LookPad, LookMouse;
    public CinemachineOrbitalFollow Orbit; public CamTuning T;
    void Update()
    {
        Vector2 ms = LookMouse.action.ReadValue<Vector2>();                // 픽셀/프레임
        Vector2 st = LookPad.action.ReadValue<Vector2>();                  // −1..1
        float dt = Time.unscaledDeltaTime;
        float yaw   = ms.x * T.mouseYaw * T.mouseScale + Curve(st.x) * T.padYawSpeed * T.padScale * dt;
        float pitch = ms.y * T.mousePitch * T.mouseScale * (T.invertMouseY ? 1 : -1)
                    + Curve(st.y) * T.padPitchSpeed * T.padScale * dt * (T.invertPadY ? 1 : -1);
        if (yaw != 0 || pitch != 0) Rotate(yaw, pitch);
    }
    float Curve(float v) => Mathf.Sign(v) * Mathf.Pow(Mathf.Abs(v), T.padExponent);
    public void Rotate(float dYaw, float dPitch)                            // 테스트도 이걸 부른다
    {
        Orbit.HorizontalAxis.Value = Mathf.DeltaAngle(0, Orbit.HorizontalAxis.Value + dYaw);   // −180..180
        Orbit.VerticalAxis.Value = Mathf.Clamp(Orbit.VerticalAxis.Value + dPitch,
                                               Orbit.VerticalAxis.Range.x, Orbit.VerticalAxis.Range.y);
    }
}

[DefaultExecutionOrder(10)]
public sealed class CamRig : MonoBehaviour
{
    public CinemachineCamera Cam; public CinemachineOrbitalFollow Orbit; public CinemachineDeoccluder Occ;
    public PlayerMotor Motor; public Transform CamTarget; public CamTuning T; public MoveTuning M;
    float fovVel, radVel, snapTimer;

    public Quaternion MoveBasis => Quaternion.Euler(0f, Orbit.HorizontalAxis.Value, 0f);   // 4-4
    public float Distance => Vector3.Distance(Cam.State.GetFinalPosition(), CamTarget.position);

    public void RecenterBehind()                                                           // L1 / Q
    {
        Orbit.HorizontalAxis.Recentering.Time = T.snapTime; Orbit.VerticalAxis.Recentering.Time = T.snapTime;
        Orbit.HorizontalAxis.TriggerRecentering(); Orbit.VerticalAxis.TriggerRecentering();
        snapTimer = T.snapTime + 0.2f;
    }
    void Update()
    {
        float dt = Time.deltaTime;
        float run01 = Mathf.InverseLerp(M.walkSpeed, M.runSpeed, Motor.PlanarSpeed);

        var lens = Cam.Lens;                                                                 // 구조체: 꺼내서 바꾸고 다시 넣기
        float f = Mathf.Lerp(T.fov, T.fovRun, run01);
        lens.FieldOfView = Mathf.SmoothDamp(lens.FieldOfView, f, ref fovVel, f > lens.FieldOfView ? T.fovUpTime : T.fovDownTime);
        Cam.Lens = lens;
        float r = Mathf.Lerp(T.radius, T.radiusRun, run01);
        Orbit.Radius = Mathf.SmoothDamp(Orbit.Radius, r, ref radVel, r > Orbit.Radius ? T.fovUpTime : T.fovDownTime);

        // 자동 정렬: Enabled 는 항상 true(그래야 OrbitalFollow 가 Center 를 인물 정면으로 갱신한다 — 소스 확인).
        // 끄고 싶을 때는 Wait 를 아주 크게. L1 강제 정렬은 Wait 와 상관없이 동작.
        bool moving = Motor.PlanarSpeed > 0.3f, running = Motor.State == MoveState.Run;
        bool autoH = T.autoRecenter == CamTuning.Auto.Always ? moving : T.autoRecenter == CamTuning.Auto.RunOnly && running;
        Orbit.HorizontalAxis.Recentering.Wait = autoH ? T.recenterWait : 9999f;
        Orbit.VerticalAxis.Recentering.Wait = moving ? T.pitchRecenterWait : 9999f;
        if (snapTimer > 0 && (snapTimer -= dt) <= 0)
            Orbit.HorizontalAxis.Recentering.Time = Orbit.VerticalAxis.Recentering.Time = T.recenterTime;
    }
}
```

- 가로·세로 `Recentering.Time` 을 같게 둔다 → `OrbitalFollow` 가 한 축에 입력이 있으면 다른 축 정렬도 함께 취소한다(소스의 "Sync recentering if the recenter times match").
- **2차**: 위 `Update` 의 `Recentering.Wait` 전환(달릴 때만 1.2초)은 1차 설계다. 지금 `CamRig.AutoAlign` 은 4-8 방식(직접 각속도 제한, `Wait` 는 늘 9999, Q/L1 만 Cinemachine 강제 정렬)이고, `CamInput.Rotate` 가 `CamRig.NoteManualLook()` 을 불러 기다림을 다시 시작한다. 공개: `AutoMode`·`SetAutoMode(mode, save)`·`NoteManualLook()`·`SinceManualLook`·`AlignRate`.
- `InputAxis` 는 구조체지만 `Orbit.HorizontalAxis.Recentering.Wait = …` 처럼 클래스의 필드를 거쳐 바로 쓸 수 있다.

### 7-8. `RigFactory` — 장면 생성과 테스트가 같이 쓰는 조립 함수 (런타임 코드)

장면 생성 스크립트(에디터)와 PlayMode 테스트가 **같은 함수로** 플레이어·카메라를 만들게 해서, 테스트가 실제 장면과 같은 설정을 검사한다. 주의: **런타임 `AddComponent` 에서는 `Reset()` 이 불리지 않는다** → Cinemachine 컴포넌트의 모든 필드를 명시적으로 넣는다(예: `Deoccluder.AvoidObstacles` 는 넣지 않으면 `Enabled = false`, `CameraRadius = 0`).

```csharp
public static class RigFactory
{
    public sealed class Rig { public GameObject Player; public PlayerMotor Motor; public Transform CamTarget;
                              public Camera Main; public CinemachineCamera Cam; public CinemachineOrbitalFollow Orbit;
                              public CinemachineDeoccluder Occ; public CamRig CamRig; public CamInput Look; public PInput Input; }
    public struct InputRefs { public InputActionReference Move, LookPad, LookMouse, Run, RunToggle, Interact, LockOn, Pause, DebugHud; }

    // visual: 이미 만든 모델(에디터 = GLB 프리팹 인스턴스, 테스트 = 캡슐 메시) 또는 null
    // input : 없으면(테스트) PInput·CamInput 을 붙이지 않는다
    public static Rig Build(Vector3 feet, float yawDeg, MoveTuning mt, CamTuning ct, GameObject visual, InputRefs? input)
    {
        var r = new Rig();

        // ── 플레이어 ──
        var p = new GameObject("Player") { tag = "Player", layer = Layers.Player };
        p.transform.SetPositionAndRotation(feet, Quaternion.Euler(0, yawDeg, 0));
        var cc = p.AddComponent<CharacterController>();
        cc.height = mt.height; cc.radius = mt.radius; cc.skinWidth = mt.skinWidth;
        cc.center = new Vector3(0, mt.height * 0.5f + mt.skinWidth, 0);
        cc.stepOffset = mt.stepOffset; cc.slopeLimit = mt.slopeLimit; cc.minMoveDistance = 0f;
        r.Motor = p.AddComponent<PlayerMotor>(); r.Motor.Tuning = mt;
        var interactor = p.AddComponent<Interactor>();

        var vis = new GameObject("Visual").transform; vis.SetParent(p.transform, false);
        if (visual) { visual.transform.SetParent(vis, false); ModelFit.Fit(visual.transform, mt.height); SetLayerRecursive(visual, Layers.Player); }
        var lean = vis.gameObject.AddComponent<BodyLean>();

        r.CamTarget = new GameObject("CamTarget").transform;
        r.CamTarget.SetParent(p.transform, false); r.CamTarget.localPosition = new Vector3(0, ct.targetHeight, 0);

        // ── 메인 카메라 + 브레인 ──
        var mc = new GameObject("Main Camera") { tag = "MainCamera" };
        r.Main = mc.AddComponent<Camera>(); mc.AddComponent<AudioListener>();
        var urp = mc.AddComponent<UniversalAdditionalCameraData>(); urp.renderPostProcessing = true;
        var brain = mc.AddComponent<CinemachineBrain>();
        brain.UpdateMethod = CinemachineBrain.UpdateMethods.SmartUpdate;
        brain.BlendUpdateMethod = CinemachineBrain.BrainUpdateMethods.LateUpdate;
        brain.DefaultBlend = new CinemachineBlendDefinition(CinemachineBlendDefinition.Styles.EaseInOut, 0.4f);

        // ── CM_Explore ──
        var go = new GameObject("CM_Explore");
        r.Cam = go.AddComponent<CinemachineCamera>();
        r.Cam.Priority = 10;
        r.Cam.Target.TrackingTarget = r.CamTarget; r.Cam.Target.CustomLookAtTarget = false;   // LookAt = Tracking
        var lens = LensSettings.Default; lens.FieldOfView = ct.fov; lens.NearClipPlane = ct.near; lens.FarClipPlane = ct.far;
        r.Cam.Lens = lens;

        var o = r.Orbit = go.AddComponent<CinemachineOrbitalFollow>();
        o.OrbitStyle = CinemachineOrbitalFollow.OrbitStyles.Sphere;
        o.Radius = ct.radius; o.TargetOffset = Vector3.zero;
        o.TrackerSettings = new TrackerSettings {                                  // namespace Unity.Cinemachine.TargetTracking
            BindingMode = BindingMode.WorldSpace, PositionDamping = ct.posDamping,
            AngularDampingMode = AngularDampingMode.Euler, RotationDamping = Vector3.zero, QuaternionDamping = 0 };
        o.RecenteringTarget = CinemachineOrbitalFollow.ReferenceFrames.TrackingTarget;
        o.HorizontalAxis = new InputAxis { Value = yawDeg, Center = yawDeg, Range = new Vector2(-180, 180), Wrap = true,
            Recentering = new InputAxis.RecenteringSettings { Enabled = true, Wait = 9999f, Time = ct.recenterTime } };
        o.VerticalAxis = new InputAxis { Value = ct.pitchDefault, Center = ct.pitchDefault,
            Range = new Vector2(ct.pitchMin, ct.pitchMax), Wrap = false,
            Recentering = new InputAxis.RecenteringSettings { Enabled = true, Wait = 9999f, Time = ct.recenterTime } };
        o.RadialAxis = new InputAxis { Value = 1, Center = 1, Range = new Vector2(1, 1) };

        var c = go.AddComponent<CinemachineRotationComposer>();
        var comp = ScreenComposerSettings.Default;
        comp.ScreenPosition = ct.screen;
        comp.DeadZone.Enabled = false;
        comp.HardLimits.Enabled = true; comp.HardLimits.Size = new Vector2(0.8f, 0.8f); comp.HardLimits.Offset = Vector2.zero;
        c.Composition = comp; c.CenterOnActivate = true; c.TargetOffset = Vector3.zero;
        c.Damping = ct.aimDamping; c.Lookahead = new LookaheadSettings { Enabled = false };

        var d = r.Occ = go.AddComponent<CinemachineDeoccluder>();
        d.CollideAgainst = Layers.Mask(Layers.Default, Layers.Ground, Layers.Wall, Layers.CamBlock);
        d.IgnoreTag = "Player"; d.TransparentLayers = 0; d.MinimumDistanceFromTarget = 0.01f;
        d.AvoidObstacles = new CinemachineDeoccluder.ObstacleAvoidance {
            Enabled = true, DistanceLimit = 0, MinimumOcclusionTime = 0, CameraRadius = ct.camRadius,
            UseFollowTarget = new() { Enabled = false, YOffset = 0 },
            Strategy = CinemachineDeoccluder.ObstacleAvoidance.ResolutionStrategy.PullCameraForward,
            MaximumEffort = 4, SmoothingTime = ct.holdTime, Damping = ct.releaseDamping, DampingWhenOccluded = ct.occludedDamping };
        d.ShotQualityEvaluation.Enabled = false;

        r.CamRig = go.AddComponent<CamRig>(); /* Cam, Orbit, Occ, Motor, CamTarget, T, M 연결 */
        lean.Init(r.Motor, r.CamRig, mt);

        if (input is InputRefs i)
        {
            r.Look = go.AddComponent<CamInput>(); /* LookPad, LookMouse, Orbit, T 연결 */
            r.Input = p.AddComponent<PInput>();  /* 액션들, Motor, CamRig, Interactor 연결 */
            p.AddComponent<CursorLock>();
        }
        // 첫 프레임에 감쇠 없이 바로 제자리: r.Cam.PreviousStateIsValid = false;
        return r;
    }
}
```

`Layers.cs`: `public const int Default = 0, Ground = 6, Wall = 7, Player = 8, PlayerOnly = 9, Interact = 10, CamBlock = 11; public static int Mask(params int[] l)`.

## 9. 자동 테스트

### 9-1. 방식

- **PlayMode 테스트**(Unity Test Framework 1.6.0). 플레이어·카메라는 `RigFactory.Build(…, visual: 캡슐, input: null)` 로 만들고, 지형은 `Lab.cs` 가 코드로 만든다(장면 파일에 기대지 않음). 1구역 테스트만 `Zone1.unity` 를 연다(`EditorSceneManager.LoadSceneAsyncInPlayMode`, `#if UNITY_EDITOR`). 장면이 없으면 `Assert.Ignore`.
- **입력 주입**: `PInput` 을 붙이지 않고, 테스트 코루틴이 매 프레임 `motor.SetMoveInput(dir, amount, run)` 을 부르거나 `PathWalker` 를 붙인다. 카메라는 `CamInput.Rotate()` 또는 `Orbit.HorizontalAxis.Value` 를 직접.
- **시간 고정**: `[UnitySetUp]` 에서 `Time.captureDeltaTime = 1f/60f`, `[UnityTearDown]` 에서 0. 매 `yield return null` = 정확히 1/60초 → 결과가 매번 같다. `-nographics` 배치에서도 빠르게 돈다(렌더 불필요).
- **입력 장치 연기 시험**(InputTests 만): `InputTestFixture` 를 상속, `InputSystem.AddDevice<Gamepad>()` 후 `Set(gamepad.leftStick, …)`, `Press(gamepad.rightTrigger)` — 실제 `HInput` 에셋 → `PInput` → 모터까지 한 번 통과하는지만 본다.

## 11. 결정 대기·열린 질문

1. **상호작용 버튼**: × (A, 제안) / ○ (일본식 확인). 기획서 4-1 은 ○ = 잡기.
2. **달리기 방식**: 기본 걷기 + R2·Shift 누르고 달리기(제안) / 스틱 끝까지 = 달리기 + 버튼으로 걷기.
3. **전력질주**: 06 메타의 `sprint 6.0` 을 M1 에 넣을지. 제안: M1 없음, 성곽 러닝 미니게임에서만 따로.
4. **계단 충돌을 경사로로** 06 빌더에 반영할지(제안: 반드시).
5. **레이어 번호 6~11** 을 06 빌더와 이 문서가 같이 쓰기.
6. **FOV 45°**: Sandbox 의 30°(모델 보기 컷)보다 넓다. 후지모토풍 망원 느낌과 길 찾기 편의 사이 타협 — 대표 확인.
7. **Y 반전 기본값**: 마우스·패드 모두 끔(제안).
8. **템플릿 입력 에셋**: `InputSystem_Actions.inputactions` 를 프로젝트 전역으로 둔 채 두고 우리 `HInput` 만 쓸지, `HInput` 을 프로젝트 전역으로 바꿀지(지금은 전자).
9. **Windows 빌드 대상**: `BatchTools.BuildWindows` 는 Sandbox 하나만 빌드한다 → M1 결과물 빌드는 Zone1 을 포함하게 바꿔야 함(구현 단계에서 `EditorBuildSettings.scenes` 를 쓰도록).
10. **카메라 자동 정렬 기본값**: ~~"달릴 때만"(제안)~~ → **2차: "걷기·달리기"로 바꿈**(대표 검수: 꺾이는 길에서 걸을 때 오른스틱을 계속 만져야 함). 일시정지 메뉴에서 달리기만·끔으로 바꿀 수 있다(4-8).
11. **자동 정렬 수치 체감 확인**: 걷기 기다림 1.8초·최대 30°/s, 달리기 1.2초·60°/s, 카메라 쪽으로 걸어올 때(150° 이상) 안 돌림. 패드로 걸어 보고 조정 여부(`CamTuning` 숫자만 바꾸면 됨).
12. **상호작용 고르기(T15)**: `Interactor`·`Interactable` 이 아직 없어 T15 는 미구현(지금은 × / E 에 알림만). M2 전 상호작용 단계에서 6장 설계대로 넣을지, M1 에 지금 넣을지.
13. **시작 자리**: 2차에서 남쪽 인도 → 차도 남쪽 차선으로 옮겼다(4-9). 인도에 두고 싶으면 후문 펜스에서 4.5m 이상 떨어진 다른 인도 자리(예: 상가 앞)로 옮겨야 같은 구도가 나온다.
