## 1. 사용법

모두 저장소 `haengin1/` 에서. 블렌더 5.2(`C:/Program Files/Blender Foundation/Blender 5.2/blender.exe`), 시스템 파이썬 3.11 + numpy + Pillow.

```powershell
# ① 생성 → concept/art/env/buildings/Z1_*.fbx + manifest   (약 7초)
& "C:/Program Files/Blender Foundation/Blender 5.2/blender.exe" -b --factory-startup -P tools/env/build_env.py
#    옵션: --zone <zone1.json> --out <폴더> --format fbx|glb|both --only HoomunN,Alley --blend <확인용.blend> --prop-geometry 1

# ② 미리 보기(게임 카메라 8곳 × 지금/키트 + 밤 2곳, 색·법선·깊이 3장씩)   (약 30초, 2배 해상도)
& "C:/Program Files/Blender Foundation/Blender 5.2/blender.exe" -b --factory-startup -P tools/env/preview_env.py -- --out <폴더> --res 1600x900 --scale 2 --night 1
#    --shots 1,7  --state before|after|both  --look "이름:x,y,z,yaw,pitch,dist,fov;..."(점검용 임의 카메라, Unity 좌표)
# ③ 외곽선·안개 얹고 나란히 붙이기 → <폴더>/<자리>_compare.png, compare_sheet.png, <자리>_night.png
python tools/env/compose_shots.py <폴더> --scale 2
# ④ 삼각형 예산 표 + perf_report.json
python tools/env/perf_report.py <폴더>/shots.json
# ⑤ FBX 안 변환값 검사(회전이 0 이 아닌 Model 수 — 메시는 0 이어야 함)
python tools/env/fbx_inspect.py concept/art/env/buildings/Z1_Alley.fbx [이름 앞부분]
```

- **결정적**: 씨앗 `envkit/geom.SEED = 20261006`. 같은 zone1.json·같은 씨앗이면 manifest 의 `geometry_sha1` 과 FBX 바이트가 같다(두 번 빌드해 확인). 블렌더 FBX 내보내기가 머리말 시각과 파이썬 `hash()` 기반 UID 를 쓰는 것을 `envkit/blend.make_fbx_deterministic()` 이 실행 중에만 고정 시각·SHA-1 로 바꾼다(애드온 파일은 손대지 않음).
- zone1.json 이 바뀌면(zone1_gen.py 다시 실행) ①만 다시 돌리면 된다. 블록 번호(`<유형>_<번호>`)는 zone1.json `blocks` 순서라, 블록을 끼워 넣으면 뒷번호가 밀린다 — Unity 쪽에서 번호가 아니라 `zone1_block`(이름) 속성으로 찾을 것.
- 씨앗을 바꾸면 모든 건물의 창 배치·색·소품이 바뀐다. 건물 하나만 바꾸고 싶으면 그 블록 이름이 키(`rng(b.key, 유형)`)라 이름을 바꾸면 된다.

## 2. 좌표·구조 규약

| 항목 | 규약 |
|---|---|
| 좌표 | zone1.json = Unity 그대로(X 동, Y 위, Z 북, 원점 혜화동 로터리). 블렌더 안에서만 (-X, -Z, Y) 로 바꿔 쓰고 FBX 는 `-Z 앞·+Y 위·bake_space_transform`(glb2fbx.py 와 같은 축) → **Unity 에서 프리팹을 원점(0,0,0)·회전 0·배율 1 로 놓으면 zone1.json 좌표 그대로** 맞는다(FBX 를 블렌더로 다시 읽어 manifest 와 비교: 50개 최대 오차 0.0006m, 소품 자리 338개 0.0008m·0.000°) |
| FBX 트리 | 뿌리 노드 없이 구역 파일 하나에 `<건물>`(빈) → `<건물>_LOD0/1/2`, `<건물>_Detail_LOD0` / `Fences_<구역>`(담·옹벽·난간을 구역마다 하나로) / `Wall_<k>` / `Pole_<k>` / `WinLit_<구역>_t##` / `Sign_<n>` / `Prop_<소품>_<n>` / `Sock_<종류>_<n>`. 메시 Model 은 회전·배율이 모두 0·1(`fbx_inspect.py` 로 확인), 자리 표시(Prop)만 Y 회전 |
| 발자국·충돌 | 상자 발자국 그대로. **충돌은 Unity 의 지금 상자 콜라이더를 계속 쓴다**(09 결정 11 — 걷는 면·M1 T14·카메라 테스트 불변). 땅 높이 2.2m 아래는 상자 밖으로 0.3m 넘게 나오는 것이 없고(골목 여유), 2.4m 위의 발코니·간판·처마·실외기만 더 나간다(발코니 0.85~1.1, 간판 0.9, 처마 0.9~1.0) |
| 층 | 3.0m, 옥상 난간 0.6m(zone1_gen 의 floors × 3 + 0.6). 1층 바닥 = 상자 윗면 − 0.6 − 층수 × 3. 비탈이면 낮은 쪽에 드러난 기초에 반지하 창 |
| 면 역할 | `envkit/zone.analyse_faces`: 걷는 면(길·계단·패드)에서 가까운 면 = **front**(출입문·간판), 걷는 면에서 보이는 옆면 = street, 안 보이는 면 = back(작은 창·실외기·배관), 옆 건물에 붙은 면 = party(창 없음). 출입문 랜드마크가 붙은 면은 그쪽이 front |
| UV | 월드 미터(벽 u = 바깥에서 볼 때 오른쪽 거리, v = 높이·윗면 (x, z)) → **재질 Tiling = 1 / 텍스처 한 장 크기(m)** — `textures/textures.json` 의 meters 를 읽어 manifest `materials.<이름>.tiling` 에 적어 둠. 간판·창문 불만 0~1 UV |
| 이름 | 모두 ASCII(FBX·Unity 안전). 한글 블록 이름은 사용자 속성 `zone1_block` 에 |

## 7. Unity 통합 체크리스트 (다음 작업자용 — Unity 는 여기서 열지 않았다)

1. **들여오기** `concept/art/env/buildings/Z1_*.fbx` 7개를 `Assets/_Project/Art/Env/Buildings/` 로. 모델 설정: Scale Factor 1, Convert Units 켬(FBX 단위 cm → m), **Bake Axis Conversion 끔**(이미 구워 놓음), Read/Write 끔, Generate Colliders **끔**(충돌은 Zone1 상자 그대로), Import Cameras/Lights 끔, Mesh Compression 끔(결정적 저장), Normals Import, **Import Visibility·Import Constraints 끔**, Material Creation Mode = Import via MaterialDescription(이름 `M_*` 로 재질 생성 → 2 에서 바꿔치기). 들여온 뒤 프리팹을 Zone1 장면 **원점(0,0,0)·회전 0·배율 1** 에 놓으면 지금 회색 상자 위에 정확히 겹친다(검증: `villa_011_LOD0` 바닥 가운데가 반시우네 다세대 (-155, 27.1, 127)).
2. **재질 연결** `Materials/Env/M_<이름>.mat` 28개(규약 21 + Stone_Base·Stone_Rubble + 키트 7)를 UTS(지금 Zone1 과 같은 툰: 1단 그림자, 배경 곱셈 .78·.76·.74, 스펙큘러 0)로 만들고, `concept/art/env/textures/<이름>.png` 를 Base Map, **Tiling = manifest `materials.<이름>.tiling`**(= 1 / 한 장 m). 키트 새 이름 7개는 텍스처 없이 평면 색(5장 표). `M_Glass_Lit` 는 발광(Emission = 텍스처, 강도 1) + 기본은 꺼짐. 재질 이름이 같으면 Model Importer 의 "Search and Remap" 으로 한 번에 붙는다.

LOD Bias 1 기준(품질 'PC').
4. **정적·그림자**: 모든 메시 Static(Batching·Occluder·Occludee), 그림자 캐스케이드는 09 3-5 대로 **2단·60m**(지금 4단이 예산 초과 원인). 창문 불·간판·디테일은 그림자 끔.

6. **소품 자리 → 프리팹**: `Prop_<소품>_<n>` 빈 오브젝트(338개, 사용자 속성 `prop`·`glb`)마다 `concept/art/env/props/<소품>.glb` 프리팹을 **자식으로 인스턴스**(위치·회전 0 — 자리 표시의 +Z 가 소품 정면, 바닥이 자리 원점). 같은 메시·재질이라 GPU 인스턴싱(docs/10 10장 LOD 3단 필수). 에디터 스크립트 한 번(`PropSockets.Populate`)으로 끝내고, 결정적 저장(StableIds)에 맞춰 이름 순으로.
7. **창문 불**: `WinLit_<구역>_t00~t09` 메시마다 `LightSpot`(Kind = Window, **Threshold = 사용자 속성 `window_threshold`**(0.05·0.15…0.95), KeepColor 끔) + 렌더러 기본 꺼짐. 그러면 `DayLight` 가 프리셋 `Windows`(밤 0.4) 보다 문턱이 낮은 묶음만 켠다 — 지금 StorySetup 이 상자 면에 붙이던 창 판 260개는 **만들지 않게**(AddLights 의 창문 판 부분을 건너뜀) 하고 셈(D07 '창문 N개')은 묶음 안 판 수(사용자 속성 없음 → 메시 면 수 / 2 또는 manifest `panes`)로.
8. **간판**: `Sign_<n>` 메시(0~1 UV, `M_Sign_Atlas`)의 사용자 속성 `atlas`(예 `band_haru_conv`)로 `concept/art/env/signs/sign_atlas.json` 사각형을 찾아 **UV 를 그 칸으로**(픽셀 [x, y, w, h] → u = x/2048, v = 1 − (y+h)/2048; 블렌더 미리 보기 `preview_env.import_kit` 에 같은 식) 하거나 재질 인스턴스의 Tiling/Offset 으로. 상호는 `tenant` 속성 글을 TMP 로 판 앞 2cm 에(글꼴 docs/10 7장). `sign_size_m` 이 판 크기. `projecting` 은 두 면이 한 Sign.
9. **빛 자리**: `Sock_shop_light`(7, 상가 유리 안 0.6m) → 점광 `ShopSign`/`ConvAwning`, `Sock_ceiling_light`(2, 필로티 천장) → 점광 `Security`, `Sock_lamp_globe`(2, 후문 기둥 구 등) → 점광 + 발광. 모두 그림자 없음, 화면당 24 안.
10. **전선 끝점**: 키트 전봇대를 쓰면(5번) 전선이 메시에 들어 있어 할 일 없음. docs/10 소품 `utility_pole` 로 바꾸려면 `Pole_<k>` 의 전선만 남기고 기둥 메시를 끄되 가로대 높이(꼭대기 −0.45·−1.45)가 소품과 맞는지 볼 것.
11. **확인**: D08 경로(밤 상가거리·새벽 와룡)로 삼각형·SetPass·GPU ms 를 다시 재고, 키트 `_preview_compare.jpg` 와 같은 8곳을 Zone1 카메라로 찍어 나란히(docs/10 P3). 걷기 테스트 T14·T15·NavMesh 가 그대로 통과하는지(충돌 불변이라 통과해야 함).

## 9. 남은 문제·결정

1. **소품 프리팹 LOD** 가 아직 없다(docs/10 P1) — 실외기 214개가 LOD 없이 들어가면 상가거리에서 소품만 1.2M. 6번 체크리스트 전에 P1 먼저.
2. 반지하 변형(semi)은 건물을 1.2m 내리므로 **상자 콜라이더보다 바닥이 낮다** — 보이기만 하고 충돌은 그대로라 걷기엔 영향 없지만, 반지하 창 앞 0.3m 턱이 보일 수 있다. 싫으면 `villa()` 의 `variant == "semi"` 확률을 0 으로.
3. 필로티(원룸 2·원룸 B)는 걸어 들어갈 수 없다(상자 콜라이더). 들어가게 하려면 Unity 에서 그 두 블록의 BoxCollider 를 1층 기둥 4개 + 뒤 벽으로 바꿔야 함(zone1_gen 쪽 결정).
4. 성곽 안쪽 LOD0 돌 쌓기(24k 삼각형)는 텍스처 `M_Granite` 와 겹쳐 보일 수 있다 — Unity 에서 보고 둘 중 하나(돌 지오메트리는 `castle_wall()` 의 `stone_face` 호출 두 줄을 빼면 사라짐).
5. 전봇대를 키트로 할지 소품 `utility_pole` 로 할지(4장) — 둘 다 있으니 Unity 에서 보고 결정. 키트 기둥은 애자·변압기·발판까지 있고 LOD 3단.
6. 담장 위 철망·빨랫줄·전선 같은 가는 것은 1080p 에서 1px 아래로 가면 깜빡인다 — 화면 공간 외곽선이 선을 대신 그려 주므로 Unity 에서 확인 뒤 굵기(`details.wire` r)를 조정.
