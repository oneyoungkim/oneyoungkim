**가장 큰 차이 5개** (스타일 프레임 8장 ↔ 같은 장면 Unity 사진 8장, 수치는 8짝 평균 — 2장)

| # | 차이 | Unity | 프레임 | 후처리로 |
|---|---|---|---|---|
| 1 | **채도가 높고 어두운 끝이 검다** — 프레임은 채도 낮은 밝은 파스텔에 검정을 들어 올린 그림 | C* 18.9 · 어두운 5% L* 10.1 | C* 13.8 · L* 16.8 | **좁혀짐**(LUT) |

**후처리로 좁혀지는 정도**(8짝 평균, 2·3장):
- 팔레트 ΔE: **8.4 → 5.1(① LUT, −39%) → 4.9(② 그늘 색) → 4.7(⑥ 끝, −44%)**
- LUT 맞춤에 안 쓴 Unity 사진 6장: **8.6 → 5.6 → 5.5(−36%)**
- 그늘 ΔE: **14.2 → 7.8 → 4.6 → 4.2(−70%)**
- 먹선 배율: 0.65 → 0.79
- 종이 결 배율: 0.72 → 0.91
- 먼 곳 대비 차: 0.39 → 0.23
- 디테일 밀도: 0.58 → 0.65 — 거의 안 바뀜

**결론**:
- 색감 차이의 대부분(팔레트·그늘)은 **LUT 한 장 + 그늘 색 표 고치기**로 싸게 닫힌다(성능 비용 ≈ 0).
- 남는 차이(디테일 밀도·빛 얼룩·웅덩이·나무 잎 덩어리)는 **화면 효과가 아니라 내용·조명 작업**이다.
- '그림 같은 붓질'(③ Kuwahara)은 수치로도(붓 배율 0.83 → 0.72) 눈으로도(계단·인물이 뭉개짐) 프레임에 가까워지지 않았다 → **하지 않는다**. 프레임은 붓 그림이 아니라 **선이 또렷하고 디테일이 많은 애니 배경 일러스트**다.

**Unity 구현 순서 권장**(4장):
1. 시간대 LUT(볼륨 Color Lookup)
2. 시간대 표(docs/10 9장)의 그늘 곱셈·스플릿 톤을 '따뜻한 회갈'로 고치고 채도 낮춤·검정 올림 → LUT 다시 맞춤
3. 먹선 색·굵기(외곽선 셰이더 1줄 + 색 경계 잔선)
4. 깊이 안개(대비 압축)
5. 빛 얼룩·웅덩이(조명 작업)
6. 디테일 밀도(키트·소품)
7. 종이 결(선택)

**자전거**: 페달 1회전 = 클립 1주기인 4종(순항·오르막 댄싱·내리막 관성·출발/정지)을 Blender 에서 해석적 IK 로 새로 만들었다(발볼–페달 오차 0mm, 루프 이음새 0°) — 6장. 남은 가장 큰 문제는 동작이 아니라 **자전거 모델이 1.72m 시우에게 작다**는 것(안장이 BB 위 0.50m·크랭크 0.10m → 순항 중 무릎이 아래에서도 85° 굽음).

## 3. 후처리 시안 결과 (오프라인, `tools/lookdev/run_lookdev.py`)

### 3-1. 단계

| 단계 | 하는 일 |
|---|---|
| ① 시간대 LUT | 묶음(새벽·낮·노을·밤·체육관·무대)마다 Unity 사진 → 프레임 색 분포를 IDT(회전 + 1차원 분위 맞춤 10번, Pitié 2007)로 옮기는 함수를 찾아 **33³ 3D LUT** 로 굽는다. 격자에서 σ0.9 칸 흐림, 세기 0.85. |

## 4. Unity 구현 계획 (효과 큰 순서)

### 4-1. 시간대 LUT — 볼륨 `Color Lookup` (효과 ★★★, 비용 ≈ 0)

**파일** `concept/art/env/lut/` — 묶음마다 2개 + 메타:
- `LUT_<묶음>.cube`: 33³, 표준 .cube, 다른 도구 확인용
- `LUT_<묶음>_URP32.png`: URP 띠 1024×32
- `lut_meta.json`: 맞춘 짝·세기·목표 그늘·선 색

묶음 = `Z1_Dawn` · `Z1_Day` · `Z1_Dusk` · `Z1_Night` · `Gym` · `Stage`. 띠와 .cube 를 같은 사진에 적용한 차이 ΔE 평균 0.22(99% 0.54) — 띠 배치(가로 = 파랑 칸 × 빨강, 세로 = 초록, 아래가 0) 확인함.

**넣는 법**(`EnvSetup.Presets` 또는 새 `LookdevSetup`):
1. PNG 를 `Art/Env/Lut/` 로 복사하고 텍스처 임포트를 맞춘다: Default · **sRGB 끔** · Mip 끔 · Clamp · Bilinear · 압축 없음 · Non-Power-of-2 None.
2. URP 에셋의 **Grading LUT Size = 32**(기본값 — URP `ColorLookup.ValidateLUT` 가 높이 = LUT 크기를 요구).
3. 시간대 프로필(`Light_{Dawn,Day,Dusk,Night}` 의 필름 볼륨 복제본)에 `ColorLookup` override 를 붙이고 texture = 해당 띠, contribution 1.0.
4. URP 는 사용자 LUT 를 톤매핑 뒤 sRGB 값에 적용한다(사진과 같은 공간) — LDR 등급 모드에서 오프라인 결과와 같아야 한다.

**시간대 섞기**: 볼륨의 텍스처 값은 보간되지 않고 0.5 에서 바뀐다.
- `DayLight.Apply` 가 시간대를 한 번에 바꾸면 그대로 둔다.
- 연속으로 바뀌는 구간(새벽 → 낮)이 생기면 `LutBlend`(새 스크립트)로 처리: 두 띠를 `Graphics.Blit` + lerp 셰이더로 RenderTexture(1024×32, sRGB 끔)에 섞고, ColorLookup.texture 에 넣는다. `ValidateLUT` 가 RenderTexture 도 받는다 — **확인 필요**.

**순서 주의**:
- 이 LUT 는 **지금 색 보정(채도 +8·대비 +5·스플릿 톤)이 들어간 사진**으로 맞췄다. 4-2 로 색 설계를 고치면 LUT 를 다시 맞춘다(`run_lookdev.py` 2분 — 새 `EnvSetup.Shots` 사진만 바꾸면 됨). 고친 뒤의 LUT 는 이동량이 줄어 더 안전하다.
- 체육관·무대 LUT 는 사진이 적어(2·4짝) 시험용이다. 무대는 장소별로(국밥집 따뜻함 / 편의점 형광 / 교실 낮빛) 나누는 것을 권장 — H6 교실에서 그늘이 벌어짐.

### 4-6. 디테일 밀도 — 내용 작업 (효과 ★★, 후처리로 안 됨)

경계 밀도 0.59배는 화면 효과로 0.65배까지만 오른다. 프레임 수준(1.0)은 **물건 수**다.

- **나무**: 잎 덩어리를 더 잘게(카드 수관 덩어리 지름 ↓, 수 ↑).
- **체육관**: 천장 조명 레일·배너·덕트 → 키트 생성기(`dense.py`) 규칙에 넣는 것이 맞다.
- **목표**: 경계 밀도 0.8배(1차).
- **비용**: 그리기 호출 — 7차 기준 978 → `Merge6` 방식으로 묶으면 +80 안쪽.

### 4-7. 종이 결 (효과 ★, 비용 ≈ 0.03ms) — 선택

### 4-8. 붓 그림(Kuwahara) — **하지 않음**

시안에서 효과 없음(3-4). 비용도 가장 크다(1080p 일반화 Kuwahara 8부채꼴 ≈ 1.5~3ms, 반해상도 0.5~0.8ms). 정 원하면 **원경 40m 넘는 곳만, 반해상도, 반경 3**.

### 4-9. 재질별 팔레트 고정(선택)

LUT 가 화면 전체를 한 함수로 옮기는 대신, 환경 텍스처·평면색 재질(`EnvSetup` 색 표 `M_* = #…`)을 오프라인으로 프레임 팔레트에 맞춰 다시 굽는 방법.

### 6-1. 무엇이 이상했나

지금 `BikeRider` 는 의자 앉기 클립(ChairSit) 위에 Humanoid IK 로:

### 6-3. 좌표·각 약속 (`bike_curves.json` 의 `note` 와 같음)

- Unity (x, y, z) = (−Bx, Bz, −By). 자전거 원점 = 두 바퀴 접지선 가운데 땅.
- **θ** = `Crank.localRotation = Euler(θ,0,0)` 의 각.
  - 0 = FBX 쉬는 자세(오른쪽 페달이 꼭대기에서 25.5° 뒤). 앞으로 밟으면 증가 — `BikeMotor.Crank` 와 같은 방향.
  - **루프 클립의 정규화 시간 = θ/360.**
- **Lean** = `LeanRoot.localRotation = Euler(0,0,Lean)`. + = 라이더 왼쪽 — `BikeVisual` 과 같은 부호.
- 동작은 '자전거에 대한' 몸 자세다(자전거가 기울면 몸은 자전거 좌표에서 반대로) → **시우와 자전거를 같은 LeanRoot 아래**에 두고 Lean 을 더한다.

### 6-4. Unity 연결 방법

1. **임포트**
   - FBX 를 `Assets/_Project/Art/Clips/Bike/` 로 복사하고 `CharSetup.Human(path, "BikeCruise", -1, -1)` 로 들인다(기존 규약: Humanoid · 바인드 포즈 아바타 — 같은 뼈라 'Copy From Other Avatar = Siwoo' 도 가능).
   - 클립 설정: Loop Time(cruise·climb·coast), **Root Transform Rotation / Position(Y) / Position(XZ) 모두 Bake Into Pose + Based Upon Original**, 압축 끔.
   - startstop 은 subClips 로 `BikeStart` 0–45 · `BikeStop` 100–150 을 루프 없이 나눈다(ride 구간은 cruise 와 같음).
2. **애니메이터**
   - 'Ride'(ChairSit) 대신 상태 BikeCruise · BikeClimb · BikeCoast · BikeStart · BikeStop. **상태의 Foot IK 켬**.
   - 전환: Posture Stand → Climb, 앉음 → Cruise, 밟지 않고 속도 > 0.3 → Coast, 정차 → Stop(끝 프레임 유지), 출발 → Start → Cruise. Cruise ↔ Climb 크로스페이드 0.2초.
3. **위상 동기**(속도에 따른 재생 속도)
   - Cruise·Climb 상태의 **Motion Time** 을 float 파라미터 `BikePhase` 에 묶고, 매 프레임 `anim.SetFloat("BikePhase", Mathf.Repeat(Motor.Crank, 360f) / 360f)`. 재생 속도를 따로 맞출 필요 없이 크랭크가 도는 만큼 정확히 페달질하고, 두 클립의 정규화 시간이 같은 θ 를 뜻하므로 크로스페이드에서도 발이 페달에서 안 떨어진다.
   - Coast 는 시간 재생. `BikeMotor` 가 관성 진입 때 크랭크를 115.5° 로(왼발 앞이 가까우면 상태 Mirror + 295.5°) 부드럽게 붙인다.
   - Start·Stop 구간에서는 `BikeMotor.Crank` 를 JSON 의 θ 곡선대로 돌린다. 정지 때 왼발을 땅에 내린 뒤에도 크랭크가 오른발 2시 자리까지 더 돈다.
4. **기울기**
   - `LeanRoot` z = 조향 Lean(지금 그대로) + 클립 Lean.
   - Climb 은 식 `8·sin(θ − 35.5°)` 로, Start·Stop 은 JSON 표로.
   - 이때 `BikeVisual` 의 박자 Sway(±8°)는 끈다(이중 기울기 방지).
5. **`BikeRider` 정리**
   - 끈다: 모델 자리 옮기기(`SeatLift`·`StandUp`·`StandFwd` → `transform.localPosition`), 척추 숙임 `SetBoneLocalRotation`. 캐릭터 루트를 자전거 원점(접지선 가운데 땅, 회전 0)에 둔다.
   - IK 는 **보정용**으로만 남긴다(가중치 0.5~1).
   - **발을 페달에 다시 붙이기**: `OnAnimatorIK` 에서 목표 = `anim.GetIKPosition(LeftFoot)`(클립 값) + (실제 `PedalL` 위치 − θ 로 계산한 클립 페달 위치), 힌트 = 무릎 앞 0.45m. 같은 시우면 보정량 ≈ 0, 자전거 배율·스케일이 바뀌거나 다른 캐릭터면 이 보정이 발을 붙인다.
   - 발 회전은 클립 값 그대로(`SetIKRotationWeight` 0) — 발목 각 곡선을 지키려고.
   - **손 목표**: JSON `grip_bar_unity` 또는 클립별 `wrist_target_unity_f0`. 자전거 FBX 의 GripL/GripR 빈 점은 레버·종 정점이 섞여 봉보다 2.5cm 뒤·1.5cm 위라 **그대로 쓰면 손이 뜬다**. 이름 GripL/PedalL 은 실제로 라이더 오른쪽(x 부호로 고름 — 지금 `BikeSetup` 처럼).
6. **시험**: 기존 `M3BikeTests` 의 HipGap·FootGap 기준을 클립 기준으로(엉덩이 ±1cm, 발 ≤ 2cm) 바꾸고, `ZBikeShots` 로 측면·정면 사진을 이 문서의 띠와 맞대 본다.
7. **다른 캐릭터(태오 등)**: Based Upon Original 이라 골반 높이·다리 비율이 시우 기준이다(엉덩이가 뜨거나 발이 벗어남). 그 캐릭터의 정식 FBX 를 넣어 `bike_anim.py` 로 다시 만드는 것을 권장(1분). IK 보정만으로 버티는 것은 비권장.

### 10-5. 자전거 (6장 → Unity)

- **치수(8장 결정 3)**: `tools/bike_split.py --saddle-up 0.12 --crank 0.16` — 안장·기둥 윗부분을 **수직으로** +12cm(기둥 축을 따라 뒤로 눕히면 안장이 4cm 뒤로 가 배달통 앞면에 엉덩이가 닿음), 크랭크 팔을 늘이고 페달은 통째로 0.10 → 0.16m(BB 높이 0.33 그대로 — 아래 페달 지면 15cm). 결과 `Art/Bike/DeliveryBike.fbx/.json`.
- **클립 다시 뽑기**(`tools/bike_anim.py`, 18초): 안장이 높아져 손잡이가 상대적으로 낮다 → 앉은 높이 맞춤과 함께 **'팔꿈치 18° 가 되게 숙임' 이분 맞춤**(+19.7°, 골반 기울기는 그 0.2배만 — 0.6배였을 때는 엉덩이가 내려가 높이 맞춤과 서로 밀어 수렴 안 함). 순항 무릎 **22~110°**(예전 85~122° — 아래 페달에서 거의 편 다리, 정상 피팅 25~35° 근처) · 발볼–페달 0mm · 손목–손잡이 최대 2.5mm · 루프 이음새 0°. 프레임마다 IK 목표(발목·손목·골반, 자전거 좌표) 17개를 `bike_curves.json` 에 더 씀. 함정: FBX 가져오기가 장면 fps 를 24 로 바꿔 클립이 Unity 에서 1.25초(24fps)로 들어가던 것 → 가져온 뒤 30 으로.
- **Unity 연결(6-4 대로 + 고친 것)**:
  - `BikeSetup.PedalClips`: FBX 4개 → `Art/Clips/Bike/` Humanoid(`CharSetup.Human`, 루트 모두 Bake·Original, startstop 은 `BikeStart` 0–45 · `BikeStop` 100–150) · 곡선 에셋 `Settings/BikeClips.asset`(θ·기울기·IK 17칸 × 프레임) · `Siwoo.controller` 상태 5 — `BikeCruise`·`BikeClimb` 은 **Motion Time = `BikePhase`(θ/360)**, `BikeStart`·`BikeStop` 은 **Motion Time = `BikeT`**(시간 재생이면 크랭크 곡선과 어긋나서), `BikeCoast` 는 시간 재생. 모두 Foot IK 켬.
  - `BikeRider`(새로): 상태 고르기 정차 → 출발(1.5초, 크랭크·기울기 = 곡선) → 순항 ↔ 관성(페달 0.25초 놓으면, 크랭크를 115.5° 로 붙임) · 댄싱(일어서기 자세, 기울기 8·sin(θ−35.5°)) · 정지(1.67초, 왼발 땅) → 정차. 크랭크는 `BikeMotor.SetCrank`, 기울기는 `BikeVisual.ClipLean`(박자 흔들기 끔). **IK 는 보정만**: 발목 = 실제 페달 + 클립 차이(땅 디딘 발은 자전거 기준 자리), 손목 = 클립 자리, 회전은 클립 그대로. 모델 자리는 옮기지 않되, 배달복 아바타가 클립 아바타보다 작아(humanScale 0.966) 골반이 2.8cm 낮게 오는 만큼만 천천히 보정.
