## 1. 좌표·축척

- **원점 = 혜화동 로터리 중심**(03_맵 3.2와 같은 점). 1구역 가운데는 로터리에서 서북서로 약 230m(게임) 떨어져 있어 좌표가 모두 x −130 ~ −274다. 장면에서 따로 옮기지 않는다 — 나중 구역을 같은 좌표로 이어 붙이기 위해서다.
- **축(Unity 기준)**: +X = 동, +Z = 북, +Y = 위. 단위 m(Unity 1 = 1m).
- **map_zones.json 에서 바꾸는 식**: `X = x × 0.25`, `Y = (y − 30) × 0.5`, `Z = −z × 0.25`
  - 03_맵 3.2의 `gameZ = z × 0.25`와 **Z 부호만 반대**다(map_zones 는 남쪽이 +z, Unity 장면은 북쪽이 +Z).
  - 수평 1/4·수직 1/2라 **경사가 실제의 약 2배**가 된다(03_맵 3.1 의도: 언덕 동네라는 느낌). 건물·계단·사람 크기는 실물 그대로다.
- **yaw**: Unity Y축 회전(도). 0이면 상자 `size[0]`(가로)이 동쪽, `size[2]`(세로)가 북쪽. 양수 = 위에서 볼 때 시계 방향. 성균관로가 동남동으로 비스듬해서 길가 건물은 yaw −6° ~ 17°로 길과 나란히 돌아가 있다.
- 모든 길·계단·패드·체크포인트의 y 는 **그 위를 걷는 면의 높이**다. 블록의 center 는 상자 한가운데, 성곽 점의 y 는 성벽 기초(땅) 높이다.

- 화면 위 가운데 HUD(TMP UGUI, 한글 글꼴): 종이색 판 + 주황 막대 + "**다음: 후문 상가거리 · 20m**"(수평 거리, 반올림). 도착하면 1.6초 "도착: …" 을 보이고 다음 목표로. 10번까지 오면 "도착: 와룡공원 전망 쉼터" 를 4초 보인 뒤 접힌다.
- 다른 코드(HUD·대사·퀘스트)가 쓸 공개 API: `RouteGuide.Current`(장면의 길잡이) · `CurrentTarget`(이름 `Name`·보일 이름 `Label`·`Pos`·`Radius`) · `Index` · `Distance` · `Finished` · `LastReached` · 이벤트 `Reached(int)`·`Completed` · `SetIndex(i)`(이어하기·디버그) · `HudLine()`. 트리거(`CPxx/트리거`, Ignore Raycast)는 나중 이벤트(대사·컷신)용 자리로 남겨 두었다.
- 테스트 T17(순서·모양·HUD)·T18(이름표 보임·숨김·겹침 0) 통과.

- **종류마다 단색 하나**. URP Lit 단색(스무스니스 0, 스펙큘러 끔) + 그림자만. 예외는 성곽(돌 줄눈)·성곽길과 돌 계단참(판석)의 생성 텍스처 × 색(6장). 장면 하늘 = 종이 크림 `#EEE3D1`, 안개 = 그보다 어두운 회색 `#D4CEC3`(선형 40~380m).
- 출처 팔레트(FUJIMOTO_STYLE 6·8장, REFERENCES 2장)에서 채도를 낮추고 **명도로 종류를 가른다**(아래 '명도 사다리').

## 14. Unity 장면 생성기에 넘길 것 (zone1.json 읽는 법)

Sandbox 와 같은 '설정 파일 → 에디터 스크립트로 장면 생성' 방식으로 `Zone1.unity` 를 만든다(`Zone1Builder.Build`, 명령은 `unity/README.md`).

| JSON | 만드는 법 |
|---|---|
| `ground[kind=heightgrid]` | 정점 73×53 메시 1장. 정점 (origin[0] + i·cell, heights[j][i], origin[1] + j·cell). MeshCollider. 색 `ground` |
| `ground[kind=pad]` | 윗면이 center.y 인 평평한 판(두께 1m, 아래로). rect 는 size = [가로, 세로] + yaw, circle 은 size[0] = 지름. 색 `pad_<surface>` |
| `roads` | 점을 잇는 띠 메시. 가로 단면은 평평, 윗면 y 는 점마다 다르다. **아래로 1m 두께**로 내려 그리면 지형과 틈이 안 생긴다(길·지형 높이차 최대 0.5m). 인도 y 에는 연석 0.15m 가 이미 들어 있다. MeshCollider. 색 = kind |
| `stairs` | 낮은 끝에서 높은 끝으로 steps 개 단(단 높이 riser, 디딤 tread, 폭 width)을 보이게만 쌓고(콜라이더 없음), 두 끝을 잇는 **보이지 않는 경사판 BoxCollider** 1장(최대 27.1°) |
| `blocks` | center·size·yaw 그대로 상자 + BoxCollider. tree 는 줄기만 콜라이더(0.6m), bush 는 콜라이더 없음 |
| `walls` | 체성 = 폴리라인을 두께 2.5 로 세운 띠(아래 = 기초 − 1.5, 위 = 기초 + 4.5, 돌 줄눈 텍스처). 콜라이더는 위로 10m 더(넘을 수 없게). 위에 `brow`(미석)·`parapet`(여장: 타 `merlon` · 타구 `crenel` · 총안 `embrasure`)·`cap`(옥개석) — 6장 단면, 보이기만(충돌 상자 안) |
| `landmarks` | kind 별 단순 도형: pole 원기둥(지름 0.3, height), lamp 원기둥 + 머리 상자(+밤 조명 자리), sign·bus_stop 얇은 판(1.2 × height), door 문짝 판(1 × 2.1, 건물 면에 붙임), wall_gate 성벽 면 판, arena·vista·npc_spot 은 M1 에선 디버그 표시만. gate·bus_stop·board·wall_gate·viewpoint·door·땅에 선 sign 에는 한글 이름표(7장 끝) |
| `spawn` | 시우 발 위치 pos, Y 회전 yaw |
| `route` | CPxx 마다 `원판`·`테두리`(걷는 면에 붙임) · `기둥`(3m)·`깃발` · `빛 기둥`(30m, 위로 투명) · `이름표` · `트리거`(반경 × 3m, Ignore Raycast). 색 `checkpoint`(길잡이 주황). 저장 상태 = 시작 때(1번 지남·2번 목표). 런타임 `RouteGuide` 가 순서대로 켠다(8장) |
| `bounds` | 네 변에 보이지 않는 벽 높이 20m |
| `colors` | 종류별 URP Lit 재질 1개씩(스무스니스 0). `wall` = 돌 줄눈 텍스처, `wallpath`·`pad_stone` = 판석 텍스처(생성 PNG, `Materials/Zone1/T_Z1_*.png`), `checkpoint` 계열 = Unlit 반투명 |

- **JSON 읽기 주의**: `points: [[x,y,z], …]`, `heights[j][i]` 같은 **배열 속 배열은 Unity JsonUtility 가 못 읽는다**. 프로젝트에 Newtonsoft 패키지가 없으니 `com.unity.nuget.newtonsoft-json`(Unity 공식)을 manifest 에 넣거나, 에디터 어셈블리에 작은 JSON 파서를 둔다.
- 컨트롤러 기준(`meta.controller`): slopeLimit 35°, stepOffset 0.3m. 시우 키 1.74m(SandboxSetup 과 같음).
- **길잡이·이름표·HUD 연결**: 빌더는 부품만 만들고, `Haengin.EditorGame.RouteSetup` 이 저장 직전 확장 지점(`BeforeSave`, M1 리그와 같은 방식)에서 `Zone1/Route` 에 `RouteGuide`, `Zone1` 에 `NameTags`(이름표 29개의 거리·우선순위), 장면 루트 `HUD 길잡이`(Canvas + `RouteHud`)를 붙인다. 한글 글꼴 에셋은 `KoreanFont.Ensure` 가 없을 때만 만든다(동적 아틀라스, 저장 파일은 늘 빈 상태).
- **결정적 생성(2차)**: Unity 는 새 오브젝트·서브 에셋에 무작위 fileID 를 매겨서, 1차는 다시 만들 때마다 `Zone1.unity`·`Zone1_Mesh.asset` 전체가 바뀌었다. 2차부터 빌더가 저장 직후 `StableIds` 로 장면 fileID 를 **계층 경로(이름#같은 이름 순번) 해시**로, 메시 서브 에셋 fileID 를 **메시 이름 해시**로 바꾸고 fileID 순으로 다시 써서, 다시 읽어 깨진 참조 0 을 확인한다. 메시 에셋·재질·필름 볼륨·생성 텍스처는 지우지 않고 제자리에서 값만 고친다(GUID 유지). 결과: 같은 zone1.json 으로 다시 만들면 장면·메시·재질·글꼴 에셋이 **바이트 단위로 같다**(2026-10-05 확인). 데이터를 바꾸면 바뀐 오브젝트의 줄만 diff 에 나온다(예: 이름표 글 2줄 바꿈 → 장면 diff 4줄). 오브젝트 이름이나 순서를 바꾸면 그 아래 fileID 가 바뀐다.
- 데이터를 고칠 때는 JSON 을 손으로 고치지 말고 `tools/zone1_gen.py` 를 고친 뒤 `python tools/zone1_gen.py && python tools/zone1_check.py` 로 다시 만든다(높이 격자가 길에 맞춰 다시 계산된다). numpy·scipy 필요.
- `Assets/_Project/Data/` 폴더와 zone1.json 의 `.meta` 는 Unity 를 다음에 열 때 생긴다. 그때 함께 커밋한다.
